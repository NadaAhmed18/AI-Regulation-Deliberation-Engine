Phase 0

The Baseline: The Sequential ReAct Bottleneck

Trace 1: 63.62s

The Problem: A single agent turn took over a minute (63.62s). Inspecting Langfuse traces revealed that the agent executed 4 sequential remote LLM round-trips per turn.

Root Cause in Prompt Design

The system prompt (system_agent.txt) commanded a strict step-by-step knowledge workflow:

1. FIRST, execute search_ai_policy to verify internal vetted database.
2. If context is missing, execute search_web.
3. If you discover a URL, execute learn_and_ingest_url.
4. Synthesize your final argument.

The model dutifully followed instructions, creating 4 network round trips where 43.1 seconds were spent purely idling for OpenRouter generations.

Phase 1

The Unified Tool Attempt & The Ingestion Trap

Trace 2: 82.58s (+18.96s WORSE)

The Hypothesis: Collapse all 3 tools into a single multi-tier function (research_policy_evidence). Let Python search Neo4j, cascade to web search if empty, and ingest URLs automatically so the LLM only executes one tool call.

The Critical Discovery

While LLM round-trips dropped from 4 to 2, total runtime jumped to 82.58 seconds! Tool execution alone exploded from 7.76s to 47.28 seconds.

Why? The unified tool executed the full scraping pipeline synchronously inside the turn loop:

  • Spun up Playwright headless browser (crawl4ai) waiting on DOM timeouts.
  • Executed Trafilatura text extraction.
  • Ran local neural reranking (FlashRank) across internal links.
  • Dispatched remote Voyage embedding calls and Neo4j Cypher write transactions.

The debate was frozen for 47 seconds just to index long-term memory that the speaker didn't even need for this round!

Phase 2

Decoupling Ingestion to Background Worker

Trace 3: 48.46s (-34.12s)

The Engineering Fix: Decouple long-term persistence from the deliberation path. Search snippets are returned immediately to the agent, while heavy scraping and Neo4j embedding are dispatched out-of-band via background threads.

# Background daemon worker in unified_research.py
if auto_ingest_web and discovered_web_urls:
    threading.Thread(
        target=_background_ingest, 
        args=(discovered_web_urls[0],), 
        daemon=True
    ).start()
The Result

Tool execution plummeted from 47.28s down to 8.71s (-81.6%). Overall step latency dropped below 50 seconds for the first time.

Phase 3

Context Explosion & The 2-Query Prompt Budget

Trace 4: 58.37s (Context Halved)

The New Bottleneck Exposed: In Trace 3, the agent discovered 13 distinct URLs. All raw snippets were stuffed into the conversation context, causing input tokens for Generation 2 to explode to 23,788 tokens. The LLM spent 15–39 seconds prefilling tokens.

The Engineering Fix

Instead of naive text truncation, we updated system_agent.txt to enforce an explicit 2-query budget:

# Research Instructions (Two-Topic Grounding)
Execute `research_policy_evidence` ONCE with exactly 2 focused queries:
1. Query 1 (Regulatory/Legal Precedent): Target a specific statute/standard.
2. Query 2 (Empirical/Impact Evidence): Target a concrete incident/metric.
Do NOT provide more than 2 queries. Formulate speech immediately after.

The Result: Input context in Generation 2 immediately halved from 23,788 to 11,531 tokens (-51.5%), and tool execution became even leaner at 5.30s.

Phase 4

Taming DeepSeek Thinking Tokens

Trace 5: 28.58s Core Agent Turn

The Bottleneck: In Trace 4, speech generation took 39.38 seconds. DeepSeek reasoning models generated hundreds of unconstrained internal Chain-of-Thought (CoT) tokens because max_tokens defaulted to Infinity.

The Engineering Fix

Configured LLMClient with bounded completion limits (max_tokens: 3000) and attached OpenRouter's reasoning governance payload:

kwargs["extra_body"] = {
    "reasoning": {
        "effort": "low"  # Restricts CoT token budget
    }
}

The Result: In Trace 5, speech generation latency dropped from 39.38s down to 12.98s (-67.0%). The entire core agent turn (Tool Call + Live Search + Speech Generation) finished in a record 28.58 seconds!

Upcoming: Orchestrator Determinism & Cloud Latency Guards

Target: ~15s Turn

The Final Frontier: In Trace 5, node_orchestrate froze for 106.8 seconds due to an upstream OpenRouter provider queue hang, wasting 335 reasoning tokens just to pick an opening speaker.

Planned Interventions
  • Deterministic Round 1 Routing: Select the first speaker deterministically on Round 1 (0.00s execution, bypassing cloud API calls).
  • Zero-Reasoning Router: Pass reasoning_effort="none" for subsequent orchestrator rounds to prevent router CoT deliberation.
